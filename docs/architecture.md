# アーキテクチャ概要

`nerves_system_atomcam2` は、Atom Cam 2 の起動とカメラ制御に必要な既存
コンポーネントを限定して利用し、その後の Linux ユーザー空間と Elixir
アプリケーションを Nerves が管理する構成です。

v0.3.0 では、Wi-Fi、mDNS、SSH、永続データ、A/B 更新、任意の Atom アプリ互換
機能、連続録画、SFTP による NAS 転送を利用できます。カメラ互換機能と NAS 転送は
明示的に有効にしない限り動作しません。

## 全体像

```text
Atom Cam 2 ハードウェア
  -> U-Boot
  -> 保護された制御カーネルと initramfs
  -> Nerves ブートマネージャー
  -> アプリケーションスロット A または B
  -> Erlang VM と Elixir アプリケーション
       |-- VintageNet / mDNS / SSH / 時刻同期
       |-- /data の永続データ
       |-- カメラ互換機能（任意）
       `-- SFTP NAS 転送（任意）
```

すべてを置き換えるのではなく、実機で検証済みのハードウェア固有部分を残し、一般的な
ユーザー空間、アプリのライフサイクル、更新、復旧を Nerves が管理します。

## 管理範囲

| 対象 | 管理するコンポーネント |
| --- | --- |
| 初期起動、制御カーネル、組み込み initramfs | 継続利用する既存コンポーネント |
| スロット選択、ロールバック | `nerves_system_atomcam2` |
| Erlang VM、Elixir release、root filesystem | Nerves system とアプリ |
| Wi-Fi、DHCP、mDNS、SSH、時刻 | Nerves の各サービス |
| ハードウェア watchdog | Nerves `heart` |
| 撮影、エンコード、Atom アプリとの通信 | 任意のカメラランタイム |
| 録画の一時保管、NAS 転送、保存期間 | Nerves アプリ |
| 書き込み可能な状態 | `/data` |

カメラランタイムには、ネットワーク、watchdog、ファームウェア更新、再起動、実際の
MicroSD ブロックデバイスを管理させません。この境界により、カメラや NAS の障害が
デバイス管理機能へ波及することを防ぎます。

## 起動とストレージ

起動の流れ:

```text
電源投入
  -> U-Boot
  -> 制御カーネル
  -> 既存 initramfs
  -> rootfs_hack.squashfs のブートマネージャー
  -> アプリケーションスロット A または B
  -> erlinit
  -> Erlang VM と Elixir release
```

初回インストールでは、MicroSD カードを次のように構成します。

| 領域 | 内容 | 通常のリモート更新 |
| --- | --- | --- |
| パーティション 1 より前 | チェックサム付き更新メタデータ 2 組 | 候補の検証後だけ更新 |
| パーティション 1 | FAT の起動・設定ファイル | 書き換えない |
| パーティション 2 | 読み取り専用アプリスロット A | 非アクティブ時だけ書き込み |
| パーティション 3 | 読み取り専用アプリスロット B | 非アクティブ時だけ書き込み |
| パーティション 4 | ext2 の `/data` | 保持 |

FAT パーティションには、制御カーネル、ブートマネージャー、ホスト名、SSH 公開鍵、
Wi-Fi 設定を保存します。ブートマネージャーは更新メタデータを検証し、起動する
スロットを選び、候補が繰り返し失敗した場合は確認済みスロットへ戻します。

## ファームウェア更新

通常のリモート更新は、実行中のスロットを上書きしません。

```text
確認済みスロット A で動作
  -> 候補をスロット B へ書き込み、検証
  -> B を起動候補に設定
  -> B で再起動
  -> ヘルスチェック成功: B を確定
  -> ヘルスチェック失敗: A へロールバック
```

候補の確定には、OTP アプリ、`/data`、更新メタデータ、ローカルネットワークが一定時間
正常であることが必要です。インターネットへの到達性は判定に含めません。

| 操作 | コマンド | 変更できる範囲 |
| --- | --- | --- |
| 完全インストール | `mix firmware.burn` | MicroSD 全体 |
| アプリ更新 | `mix firmware`、`mix upload nerves.local` | 非アクティブスロットと更新メタデータ |

SSH 公開鍵で更新操作へのアクセスを制限し、fwup とデバイス側 updater がアーカイブ、
対象プラットフォーム、アーキテクチャ、書き込み結果を検証します。

## 実行時の監視

サンプルアプリでは、標準の Nerves サービスと任意機能を OTP supervision tree で
監視します。

```text
Atomcam2NervesApp.Supervisor
  |-- TimeSync
  |-- FirmwareHealth
  |-- VendorCamera（任意）
  |-- RtspServer（任意）
  |-- NasExporter.SFTP（任意）
  `-- NasExporter（任意）
```

- VintageNet が `wlan0`、Wi-Fi 接続、DHCP を管理します。
- USB Ethernet アダプタを接続すると、`atomcam2-eth-driver` がドライバを
  ロードし、VintageNet が `eth0` を DHCP で構成して有線を優先します。
  ケーブルやアダプタがない場合は Wi-Fi へフォールバックします。
- `mdns_lite` が `nerves.local` を通知します。
- NervesSSH が IEx、SFTP、ファームウェアアップロードを提供します。
- NervesTime が `/data` の時刻を復元して同期します。
- RtspServer は、カメラ互換ランタイムが動作している間だけ RTSP 配信を行い、
  停止すれば配信も止めます（フレームの供給元がそのランタイムのため）。
- 任意機能の失敗は状態として報告し、Nerves の基本機能は停止させません。

## カメラ互換機能

標準 Atom アプリに必要な既存バイナリを、パスとライブラリに互換性を持たせた
`chroot` で実行します。この環境はセキュリティ sandbox ではありません。

カメラランタイムは必要な設定を `/data/atomcam2-vendor-camera/configs` へ複製し、
必要最小限のカメラ、ISP、音声、エンコーダーモジュールとプロセスだけを起動します。
互換処理により、Nerves が管理する Wi-Fi 状態を参照できる一方、実際の watchdog、
ネットワーク設定、内蔵フラッシュ、MicroSD、再起動は操作できないようにします。

## 録画と NAS 転送

作成中の 1 分間の録画はカメラランタイム専用の一時領域に置かれます。録画が完了
すると `/data` の spool へ移動し、その時点で初めて転送対象になります。

```text
録画中の MP4
  -> 完了したローカル MP4
  -> SFTP で .uploading として送信
  -> サイズを検証して正式名へ変更
  -> ローカルに転送完了を記録
  -> 設定に従ってローカルと NAS を整理
```

主な安全規則:

- `YYYYMMDD/HH/MM.mp4` 形式の完了済み録画だけを扱う
- 専用 SSH 鍵と登録済みホスト鍵を使用する
- 一時名で送信し、サイズ検証後に名前を変更する
- 同じサイズの転送済みファイルは再送しない
- 未転送のローカル録画は容量上限を超えても削除しない
- 保存期間を過ぎた、想定形式の NAS 録画だけを削除する

NAS に接続できない場合は後で再試行します。録画、起動、SSH、ファームウェアの
ヘルスチェックには影響しません。

## 永続データ

ファームウェアは読み取り専用で交換可能です。継続して必要な状態は `/data` に
保存します。

```text
/data
  |-- .nerves_time
  |-- nerves_ssh/
  |-- atomcam2-update/
  `-- atomcam2-vendor-camera/
       |-- auto-start.conf
       |-- configs/
       |-- spool/record/
       |-- nas-export.conf
       |-- nas-ssh/
       `-- nas-exported/
```

`/data` は再起動、リモート更新、スロット変更、ロールバック後も保持されます。起動時に
アンマウント状態で検査・修復し、安全にマウントできない場合は自動初期化せず利用不可の
ままにします。

## 障害時の動作

| 障害 | 想定される動作 |
| --- | --- |
| カメラを起動できない | Nerves、Wi-Fi、SSH、更新、復旧は継続 |
| カメラが動作中に異常になる | 状態を報告し、自動再起動ループは作らない |
| NAS に接続できない | 後で再試行し、未転送録画はローカルに保持 |
| アップロードが中断する | 一時ファイルを削除し、現在のスロットを継続 |
| 更新候補が繰り返し起動に失敗する | 確認済みスロットへ戻る |
| `/data` を修復できない | 暗黙に初期化せず利用不可にする |

この設計では、便利さよりも復旧可能性と観測可能な失敗を優先します。
