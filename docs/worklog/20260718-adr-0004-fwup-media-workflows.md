# 20260718 ADR 0004 fwup media workflow verification

## Result

The fwup `complete` task successfully created a bootable AtomCam2 MicroSD
card using the standard Nerves `mix burn` workflow.

The device booted from the generated card, joined Wi-Fi, published
`nerves.local` through mDNS, and accepted an SSH connection into the
interactive IEx shell.

## Complete task verification

The firmware was written to a physical MicroSD card with:

```sh
mix burn \
  --firmware _build/atomcam2_prod/nerves/images/atomcam2_nerves_app.fw \
  --device /dev/sda \
  --task complete
```

The command completed successfully.

After reinserting the card, the media contained one FAT partition labeled
`ATOMCAM2`.

The partition contained:

```text
authorized_keys
factory_t31_ZMC6tiIDQN
hostname
nerves-provisioning.conf
rootfs_hack.squashfs
```

The protected control kernel matched the required SHA-256:

```text
b50658eac32b57fdcb20383d82a54e6439acd7a3f7e9cb8b43edf4a4b89b03bc
```

The written `rootfs_hack.squashfs` matched the final application-merged
root filesystem generated by the Nerves application build.

## Hardware boot verification

The device became reachable as:

```text
nerves.local
192.168.10.117
```

SSH opened the expected interactive shell:

```text
Interactive Elixir (1.20.2)
iex(atomcam2_nerves_app@127.0.0.1)>
```

The runtime reported:

```text
Hostname: nerves
wlan0: 192.168.10.117/24
```

This proves the physical path:

```text
fwup complete
-> MicroSD
-> protected AtomCam2 kernel
-> final Nerves root filesystem
-> application
-> Wi-Fi
-> DHCP
-> mDNS
-> SSH
-> IEx
```

## Upgrade task verification

The fwup `upgrade` task was tested against a complete raw image.

The task updated:

```text
factory_t31_ZMC6tiIDQN
rootfs_hack.squashfs
```

The task preserved:

```text
hostname
authorized_keys
nerves-provisioning.conf
persistent-test.txt
```

The updated kernel retained the required protected SHA-256, and the updated
root filesystem matched the final application-merged SquashFS.

## Firmware metadata finding

The fwup `complete` task does not currently write `nerves-firmware-metadata.conf`.

An isolated fwup 1.16.0 probe confirmed that `${FWUP_META_UUID}` remains literal in ordinary file-resource contents. The generated `.fw` bundle therefore remains the authoritative source of firmware identity.

The FAT-side metadata file is optional. The implementation will not require unsafe fwup commands or post-write media mutation solely to synthesize it. Its absence did not prevent boot, networking, SSH, or IEx.

## Conclusion

The fwup `complete` task has achieved physical boot parity for the current
AtomCam2 application workflow.

The fwup `upgrade` task has achieved the required media-preservation behavior
in raw-image testing.

Remote firmware upload remains rejected.
