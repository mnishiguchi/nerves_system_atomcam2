## 実装構成

| モジュール | 責務 |
| --- | --- |
| `Atomcam2NervesApp.Dashboard` | Facade。公開 API は `enable/1` と `enabled?/0` のみ |
| `Dashboard.Server` | httpd インスタンスの所有・起動・停止、設定の永続化(`/data/atomcam2-dashboard/enabled.conf`)。supervision tree の独立 child |
| `Dashboard.Router` | 3 ルートの振り分けと **JSON 正規化**(エンコード層) |
| `Dashboard.Collector` | **内部 Map のみ**を返す。カテゴリ毎の関数に分割、call タイムアウト 200ms、全カテゴリ `unavailable` 縮退 |
| `Dashboard.View` | HTML 1 枚(インライン CSS・meta refresh 10 秒・JS なし) |

ルート(提案書どおり):

- `GET /status.json` — 正規 API(camera / rtsp / system / memory /
  network / firmware / storage / logs の 8 カテゴリ)
- `GET /` — 同データの HTML ビュー
- `GET /healthz` — `ok`

ON/OFF(提案書どおり、既定 OFF):

```elixir
Atomcam2NervesApp.Dashboard.enable(true)   # 起動
Atomcam2NervesApp.Dashboard.enable(false)  # httpd ごと停止(ポート閉鎖)
```

画面キャプチャは [README](../README.md#状態モニタリング) に掲載
(`docs/assets/dashboard.png`)。

## 実装中に判明したこと(提案書からの差分)

1. **OTP `:json` は Elixir の `nil` を文字列 `"nil"` にする**(JSON null は
   atom `:null`)。エンコード層(Router)で `nil → :null` の深い正規化を
   入れて解決。Collector は表現非依存のまま(提案書のアーキテクチャ
   どおり、変更はエンコード層に閉じた)
2. **`Dashboard.Supervisor` ではなく `Dashboard.Server`(GenServer)** に
   した。httpd は `:inets.start/stop` で管理する単一インスタンスであり、
   子プロセス群を監督する Supervisor よりも「所有する GenServer」が実態に
   合う。Facade(`Dashboard`)+ 実体、という提案書の責務分離は維持
3. **View は EEx ではなくヒアドキュメント補間**にした。テンプレートが
   1 枚で分岐も少なく、コンパイル時 EEx と実質同等(実行時テンプレート
   エンジン無しの意図は満たす)
4. カテゴリの実装差分:
   - `camera.camd_pid / rss` は **`camd_alive`(boolean)** に変更
     (MuonTrap 経由では OS PID を素直に取れないため。必要になれば
     `/proc` 走査で追加可能)
   - **NAS カテゴリは未実装**(NasExporter は vendor 録画前提で現在
     待機状態のため。native 録画が入った時点で追加)
   - **フレーム心拍・stall ストライクは未実装**(`RtspServer` は vendor
     経路用で native 心拍が未整備。残件の「心拍監視の native 対応」と
     同時に追加)
   - `rtsp.announce_history` を追加(起動アナウンス履歴の直近 3 行。
     ブート毎の成否がブラウザから見える)

## 運用

- 既定 OFF。使うときだけ `enable(true)` → `http://<ip>/`
- OSD デバッグパネル(映像上)との使い分け: 映像を見ながらの確認は OSD、
  **camd 停止時の診断・機械可読 API** はダッシュボード

## Phase 2 実装(2026-08-04 追記)

提案書の Phase 2(操作 + 認証)も実装・実機検証済み。

- 追加ルート: `POST /announce`(テスト発声 = 起動アナウンス再生)/
  `POST /reboot`(1 秒後に `Nerves.Runtime.reboot/0`。応答を返してから
  再起動)
- **認証は提案書の方針どおり**: GET は匿名のまま、**POST のみ HTTP Basic
  認証**(ユーザー `admin`)。パスワードは IEx から設定し
  (`Dashboard.set_password("...")`、`nil` で削除)、
  `/data/atomcam2-dashboard/password.conf`(0600)に永続化。
  **未設定の間は操作を全拒否**(安全側の既定)。比較は SHA-256 の
  定数時間比較
- HTML にボタン(`confirm()` ダイアログ付き)。CSRF 対策は入れない
  (読み取りは副作用なし・書き込みは認証必須、という提案書の判断どおり)
- 検証(実機): 未認証 POST=401、誤パスワード=401、正パスワードで発声・
  再起動が実行、パスワード削除後は再び 401
